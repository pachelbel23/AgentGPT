## 2026-08-10 - Nested Prisma Writes and Component Memoization
**Learning:** In highly interactive applications like AgentGPT, batch operations (like creating an agent along with N tasks) done sequentially or via multiple parallel Promises trigger a severe N+1 writes bottleneck in the database. Utilizing nested Prisma writes (e.g. `prisma.agent.create` with nested `tasks: { create: ... }`) collapses these operations into a single transaction, reducing network round-trips from O(N) to O(1) and ensuring data atomicity. Additionally, wrapping frequently-appended list item components (like `ChatMessage` and `Task`) in `React.memo` with explicit `displayName`s avoids O(N) redundant re-renders as new items stream in.
**Action:** Always refactor sequential database writes into nested Prisma creates or `createMany` operations. Ensure list item components in high-frequency list rendering views are wrapped in `React.memo` to prevent main-thread blocking and drop-frame rendering on the frontend.
