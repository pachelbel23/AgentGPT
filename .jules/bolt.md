## 2025-07-24 - [Nested Prisma Writes for Agent Creation]
**Learning:** Sequential Prisma queries (e.g. creating an Agent first, then doing mapped `prisma.agentTask.create` calls) produce an N+1 query pattern. For 50 tasks, this leads to 51 separate database insertions. Using standard Prisma nested relation writes (`tasks: { create: [...] }`) groups the operation under a single transaction, reducing network roundtrips to 1 and improving SQLite write latency by ~91.5% (from 270ms down to 23ms). On production MySQL/PostgreSQL databases, this benefit is even more pronounced because of the elimination of sequential network latency.
**Action:** Always favor Prisma nested writes (`create` or `connectOrCreate`) and batch mutations over sequential `Promise.all` mapping of multiple write operations to minimize database connections and connection overhead.
